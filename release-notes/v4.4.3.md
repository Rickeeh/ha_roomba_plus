# Roomba+ 4.4.3

**The *Cleaning mode* selector reaches the robot: the Start button, room
and zone cleaning all use it now, as 4.4.2 meant them to.**

[Upgrade notes →](../docs/UPGRADING.md#v443--from-v442)

---

## The selector was never read (@homux-tech, #214)

@homux-tech set *Cleaning mode* to mopping on 4.4.2, pressed Start, and
his Combo 505 Plus vacuumed.

The code that reads the selector looked it up under a different id
than the one the selector registers with: `<robot id>_prime_cleaning_mode`
against `roomba_plus_<robot id>_prime_cleaning_mode`. The lookup never
found it, so the selected mode reached no command, on either
generation, since 4.0:

- not the **Start button** (new in 4.4.2);
- not **room or zone cleaning** that names no mode itself;
- and so not the Classic *Vacuum and mop* value fixed in 4.4.2 either.

A `cleaning_mode` given in `roomba_plus.clean_room` or `clean_zone`
itself was never affected. That is why his earlier test with
`cleaning_mode: mop` mopped. The tests faked the lookup and agreed with
whatever id they were asked for.

- **Both sides now build the id the same way.** It is the id the
  selector always had, so nothing in your installation changes or moves.
- **The new test uses Home Assistant's real entity registry** and the
  real selector's id.

## Start on a docked Prime robot

A Prime robot names its map only while it is localised. Docked, it
names none, so 4.4.2's whole-home start with a mode found no rooms and
fell back to a plain start.

- **The map the robot last named is used, else the account's only map.**
  With several maps and none remembered since Home Assistant started,
  the plain start still goes out.
- **The log says why** whenever a start goes out without the selected
  mode: a mission is open (it is resumed), or the rooms of the robot's
  map are not known.

## Under the hood

- `const.cleaning_mode_select_unique_id()`, used by
  `PrimeCleaningModeSelect` and `room_cleaning._selected_cleaning_mode()`.
- `PrimeRoomCleaning.whole_home_room_ids()` takes the map from
  `where_the_robot_is()`, else the only map in `_all_map_ids()`.
- `IRobotVacuum.async_start()` logs a start that leaves the mode behind.

## Tested

- The full suite passes on Home Assistant 2025 and 2026; ruff, the
  typing baseline and the per-module coverage floors pass.
- The new tests fail against 4.4.2: the selector is not found in a real
  registry (Classic and Prime), and a docked robot with one map or a
  remembered one gets no rooms.
