# Roomba+ 4.3.6

**Presence scheduling survives a robot that is off the network and
works on Prime at all, the total energy sensor no longer dips after a
charge, a skip after a restart keeps the mission's plan, the account
picker passes Hassfest, and contributors get one command for every
check. Two of these are contributions by @mdarocha.**

[Upgrade notes →](../docs/UPGRADING.md#v436--from-v435)

---

## Presence scheduling and an unreachable robot (#208, @mdarocha)

With a Classic robot off the network, every presence change logged
"Task exception was never retrieved" with `RoombaConnectionError`:
nothing in the presence manager caught the failed write.

- **A failed write is logged as a warning** instead, on arrival and
  at the end of the away delay, and the manager's record of what it
  paused stays as it was. (#208)
- **It is tried again** (4.3.6). Before, the next attempt came only with
  the next presence change, so with everyone away all day one missed
  write kept the schedules paused. Now the change is tried after a
  minute, five, a quarter of an hour, then every half hour, without
  waiting the away and clean delays again. A Classic robot that
  reconnects is tried at once. Only the first failure is a warning;
  the success after it is logged once.

## Presence scheduling on Prime never worked

@mdarocha also noticed that the list of Prime schedules the manager
switched off was only created at the end of a completed away cycle,
and that cycle needs the list. On every Prime robot, the first pause or
resume failed with `AttributeError`. The list now exists from the
start.

Two more gaps on the same path:

- **A schedule read that failed counted as done.** The Prime cloud not
  answering looked like an account without schedules, and the manager
  recorded a resume or pause that never happened. It is now a failure,
  tried again as above.
- **A resume that failed forgot what to resume.** The schedules were
  struck off the list before the write, so after a failed write they
  stayed off. They are struck off once the write went through.

Prime cloud errors are now caught like Classic's.

## Total energy consumed dipped after a charge (#209, @mdarocha)

`total_energy_consumed` (`total_increasing`) is clamped to a stored
high-water mark so it never falls. The mark only advanced at the end of
a mission, but the charge after it raises the cycle count and then
lets the capacity estimate settle a little lower. Between the two the
sensor fell back, and Home Assistant recorded negative consumption for
that hour in the energy statistics (-0.014 kWh, twice, on his robot).

- **The mark advances whenever the value rises**, and is saved then,
  about once per charge cycle. Saving also keeps it across a restart
  before the next mission.

## A skip after a restart kept no plan

4.3.5 keeps the command that started a mission, so a pause, resume or
skip does not wipe the planned rooms. After a restart of Home Assistant
it was not known until the robot reported a new command: the robot
sends its whole state when it connects, before Roomba+ listens for it.

- **The start is taken from the robot's state at setup**, unless that
  is already a pause, resume or skip. The diagnostics show it
  (`field_evidence.mission_command`) right after a restart.

## Hassfest

The Hassfest check on GitHub has failed on every run since 4.3.0b1, for
two reasons:

- **The account picker's two fixed choices had keys Home Assistant
  rejects** (`__other__`, `__none__`). They are `other_account` and
  `no_account` now. Nothing stored them: they only exist while the setup
  dialog is open. `scripts/check_translations.py` checks selector options
  from now on; it looked only at states and fields, and its failure
  report could not be reached.
- **roombapy 2.0.2 differed from the 1.9.1 Home Assistant pinned.**
  Home Assistant's own roomba integration moved to roombapy 2.0.2
  (home-assistant/core#184198, merged into dev on 10 October 2026), so
  this goes away once Hassfest checks against that state.

The test runs also no longer warn about Pillow's `getdata()`, which
Pillow 14 removes.

The manifest now also names the `mqtt` logger. roombapy 2.x and
roombapy-prime talk MQTT through aiomqtt, which logs under that name, so
Home Assistant can tie those lines to Roomba+.

## For contributors

- **`AGENTS.md`** says how this repository is worked on: a test that fails
  without its fix, one test file per module, both Home Assistant
  versions, placeholders instead of private data, no texts from the
  iRobot apps. `CLAUDE.md` points Claude Code to it.
- **`scripts/check_all.sh`** runs every check the CI runs, in one
  command.
- **A pull request template** asks for the robot it was tested on.
- **A new CI job, "No Private Data"**, reads the lines a change adds and
  fails on private IPv4 addresses, MAC addresses, robot ids and
  passwords, e-mail addresses outside example domains, and cloud keys or
  tokens. It reports where and what kind, never the value. A robot id in
  two test files was replaced with a placeholder.

## Under the hood

- `presence_manager`: `_UNREACHABLE` (`RoombaConnectionError`,
  roombapy-prime's `CloudError`, `SchedulesUnavailable`);
  `RETRY_DELAYS_S` (60, 300, 900, 1800); `_robot_unreachable()`,
  `_robot_reached()`, `_retry()`, `_on_connection_state()` registered
  through roombapy's `register_on_connection_state_callback`;
  `_act_on_all_away()` split out of `_away_delay()`; `_all_away()`
  shared by both. `_paused_schedule_ids` declared in `__init__`.
  `_set_schedules_paused()` raises `SchedulesUnavailable` when
  `async_read_schedule_containers()` returns None.
- Tests that built the manager without its constructor now use it;
  that is how the missing list went unnoticed.
- `sensor_helpers._total_energy_consumed_kwh()` advances
  `RobotProfileStore.lifetime_energy_kwh_high_water` and schedules
  `async_save()` on a rise (#209), as `_battery_health_pct()` does for
  its baseline.
- `callbacks._cached_last_command()`; `make_mission_callback()` holds
  it at creation, and a message without `lastCommand` fills an empty
  `RoombaData.mission_command` from it.
