# Roomba+ 4.4.2

**The Start button cleans in the selected cleaning mode, as the iRobot
apps do; a Prime start that the pad fault rules out is refused with the
reason; "Vacuum and mop" on a Classic mopping robot sends the value
Classic takes; a skipped room no longer counts as cleaned; two map
settings that were easy to mix up have names that say what they do; and
the diagnostics show a command's settings and which turn of the path
fits the rooms, without the floor plan.**

[Upgrade notes →](../docs/UPGRADING.md#v442--from-v441)

---

## The Start button uses the cleaning mode (@homux-tech, #214)

@homux-tech set the cleaning mode on a Combo 505 Plus to mopping,
started the robot, and it vacuumed. The *Cleaning mode* selector went
only with room and zone commands; a plain start sent a bare "start",
and the robot cleaned in its own setting from the iRobot app.

How both iRobot apps start the whole home in a chosen mode was read
from their code (Classic 7.18.0, Prime 3.2.0): neither writes a setting
first, both put the mode into the start.

- **Classic:** the start carries the mode in its `params`, without a
  map or rooms, as the Classic app sends it. Only *Vacuum*, *Mop* and
  *Vacuum and mop*; the Classic app has no *Vacuum then mop*, so that
  choice starts as before.
- **Prime:** the start is a room command listing every room of the map
  the robot is on, each with the mode -- the Prime app's own form, and
  the one @homux-tech confirmed: `clean_room` with *Mop* put the pad
  down and mopped. Only from an idle robot; a paused run is resumed as
  before, since a room command into an open mission is refused. Where
  the rooms of the map are not known, the bare start goes out.
- **Only on a robot that can mop**, by its own capabilities. A vacuum,
  or a robot that has not reported them, starts exactly as before.
- **The `cleaning_mode` field of both actions no longer says "Prime
  robots only".** It has worked on Classic mopping robots too for some
  time; the text had not followed.

## A start the pad rules out (Prime)

The Prime app refuses a mission start while one of four faults is
active. Roomba+ only reported them (the *Start blocked* sensor). A
start is now refused with the vendor's text for the fault, but only for
what the fault itself rules out: mopping with the pad plate missing
(290) or without a cloth (234), vacuuming with the plate fitted (287),
anything with the robot off the floor (286). A start that names no mode
is refused only with 286. Docking, stopping, pausing and the dock
controls are never held back -- the app's greyed-out dock was
@chairstacker's complaint, and that stays as it was.

## What a Classic robot received

The Classic start with a mode follows the app's code; no Classic robot
has been seen taking it yet. The robot records the last command it
received, settings included, and the diagnostics cut that record down
to its ids. They now carry the cleaning settings too (mode, pad
wetness, scrub, passes), for the command and for each room, and the
same settings for schedules that name no rooms. No days, times or
positions. If you have a Classic robot that mops: start it in a mopping
mode, once from Home Assistant and once from the iRobot app, and attach
the diagnostics of each to #214. On Prime the robot's record carries no
settings.

## "Vacuum and mop" on Classic

Checking the cleaning mode turned up a wrong number. "Vacuum and mop" is 32 on
Prime and 6 on Classic. The selector held the right table for each
robot, but the code that reads it for a room or zone command looked the
name up in Prime's table. A Classic robot with "Vacuum and mop" selected
was sent 32 for each room or zone it was asked to clean, a value no
capture shows Classic accepting.

- **It reads the robot's own table now.** "Mop", "Vacuum" and "Vacuum,
  then mop" are the same in both tables and were never affected, nor
  was a `cleaning_mode` given in the action itself, which was already
  read against the right table.

## Under the hood

- `room_cleaning._selected_cleaning_mode()` maps the selector's state
  through `cleaning_modes_for()` for the robot's connection type,
  instead of `PrimeCleaningModeSelect.MODES`.
- `diagnostics._mode_params()` with `_MODE_PARAM_KEYS`;
  `smart_map.last_command_summary` adds `params` and `region_params`;
  `smart_map.clean_schedule2_whole_home` lists command and settings of
  schedules without rooms.
- `position_room.in_room_by_turn()` and `TURN_ANGLES`;
  `PositionRoomTracker.observe_turns()`, `in_room_by_turn` in its
  diagnostics; `image._observe_turn_candidates()`, fed in
  `_handle_live_position()` before the turn, only in phase `run`.
- `diagnostics._debug_logging_on()` gates `last_mission_trajectory_mm`;
  `diagnostics._schedule_cmd()` reads `cmd` and `cmdStr`.
- `const.ROOM_EVENT_CLOSED_AT_END_STATUSES` adds 3.
- `MissionTimerStore.skipped_rooms` and `skipped_rids`, kept by
  `mark_skipped(..., rid=)`, also for a room a position had already
  entered, and across a replan. The Classic skip's record names the
  room's id; the last room's `dock` is tracked as a skip.
- Mission records gain `skipped_rooms` and `skipped_rids`
  (`callbacks._skipped_rooms()`); `last_cleaned_rooms` leaves them out.
  `MissionStore._timeline_cleaned_rids()` and `record_region_ids()` leave
  out `skipped_rids`.
- `services.yaml`: the `cleaning_mode` descriptions of `clean_room` and
  `clean_zone`.
- `strings.json` and the eight translations: label and description of
  `live_path_turn` and `map_rotation`.
- `IRobotVacuum.async_start()` with `_start_mode()`, `_robot_o_mode()`
  and `_prime_start_whole_home()`; `PrimeRoomCleaning.whole_home_room_ids()`.
- `const.prime_blocking_faults()` (moved from `sensor_prime`) and
  `const.prime_start_refusal()`; `room_cleaning.raise_if_prime_start_blocked()`,
  called by the Prime start and at the one point every Prime region
  command passes; exception `prime_start_blocked` in all eight languages.
- `docs/FEATURES.md`: the *Cleaning mode* row, *Start blocked*, the two
  map settings; `docs/AUTOMATIONS.md`.

## Tested

- The full suite passes on Home Assistant 2025 and 2026; ruff, the
  typing baseline and the per-module coverage floors pass.
- The new tests fail against 4.4.1: Classic gets 32 instead of 6 (Prime
  passes before and after); the diagnostics carry no settings, no turn
  counts, skip schedules stored as text and include the trajectory
  without debug logging; the end check waits for a room on status 3, a
  skipped room is recorded as cleaned, a plain start sends no mode and a
  start against a pad fault goes out. The guards pass before and after:
  a vacuum starts bare, the dock is never held back.
