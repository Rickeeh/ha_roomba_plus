# Roomba+ 4.5.0b4

**The fourth beta of 4.5.0.** Everything in 4.5.0 is listed in
[4.5.0](v4.5.0.md); this page is what changed since
[4.5.0b3](v4.5.0b3.md).

Needs *Show beta versions* in HACS. Built on **roombapy-prime 0.8.2**,
which Home Assistant installs with it.

---

## Automatic learns the turn of the path

@nareso's j7+: *Align the path with the rooms* on *Automatic* chose
180°, and the cleaning path lay turned against correctly drawn rooms;
0° by hand fixed it. An i7+ had read −90° where 0° was right. Automatic
took the angle from the map the robot saved, and that was wrong on two
of the three robots whose owners checked.

- **The path decides now.** Every position asked from the robot is
  tried at all four angles and counted per map: how many land in a
  room. After 300 positions (about five minutes of cleaning), an angle
  that puts at least half of them in a room, and half as many again as
  the angle in force, becomes Automatic's.
- **During the run:** the path already drawn turns with it, and room
  tracking follows from there. The next run starts with that angle.
- **A map turned in the iRobot app** starts its counts afresh.
- **A fixed angle is not touched.** If you set one because Automatic
  was wrong, you can switch back to Automatic: it has been counting.
- Diagnostics: `path_turn_learning` (counts, no map id) and
  `requested_path_turn_source: learned`.

## iRobot's article and the app's words in more places

- **`help_url` on *Status – Error*** while it shows an error, not only
  on *Error – Last code*.
- **The readiness sensor on a refusal to start:** `app_label` and
  `description` are the Classic app's words for it, in your language
  -- "Re-install the bin." rather than the firmware's name we used to
  translate -- and `help_url` iRobot's article. The state stays the key
  (`no_bin`, ...).
- **The maintenance list** links iRobot's article for the error that
  brought an entry, beside our guide; the maintenance event carries it
  as `help_url`, and the maintenance blueprint links it in its
  notification (`notification_help_url` for your own action).
  Re-import the blueprint to get it.
- **Error 17 ("Path blocked") does not point to the camera window.**
  Checked against iRobot's page: eight of its ten steps are about the
  room. Its article is linked from the error instead.

## Fixed

- **A Prime robot's runtime of 56 years** (@jdmasuta, Roomba Plus 410
  Combo): the robot reported `runtimeStats.hr` 497874 three weeks after
  it was set up, beside 476 powered-on hours. The *Lifetime runtime* sensor now
  reads unknown when the runtime is longer than the robot has been
  switched on (with a day's slack) or, without that figure, longer than
  ten years. The attributes keep what the robot said (`reported_hours`)

  show the counter itself counts correctly, in hours and remaining
  minutes, from a start about 497,000 hours too high, so on such a

  that holds, and shows itself again if the value comes back into
  range. If you hide or show it yourself, that choice stands. His readings around a run

- **A maintenance reset on a Prime robot was booked at 0 hours**, since
  4.0.0a14: it read the runtime from a key no robot sends. It reads the
  same meter as *Lifetime runtime* now, with the same check; a value
  that cannot be true is not written in as the starting point, and the

- **A cloud answer with the robot's own area counter** (a summary

  prepares the built-in setup dialog after every restart, and that

## Prime: where a reconnect spends its time

@glowpartyy's robot drops its MQTT connection every couple of minutes
(`[code:128] Unspecified error`), and one resume took 40 seconds with
nothing logged in between. roombapy-prime 0.8.2 says where the time
goes:

- **The "watch resumed" warning** gives the total and each stage:
  waiting for a reconnect already in progress, a login, connecting,
  failed attempts with their backoff, and the subscription check.
- **The diagnostics** carry the last 20 of these under
  `prime.mqtt_reconnects`: when, the broker's reason, the durations.
  No topic, id or payload.
- **No robot id in these lines any more.** They logged the whole topic,
  `$aws/things/<robot id>/...`, and the token-refresh warnings the id
  itself. They show its last four characters now.

The reconnecting itself is unchanged; this is to find the cause.

## Tidied

- **Roomba+ no longer reads the Classic error table itself at
  start-up.** b3 did, as a guard against the blocking-call warning,
  and roombapy-prime 0.8.1 reads the table when it is loaded anyway;
  the second step only repeated a lookup. A test now holds the library
  to it: an error lookup must not open a file.
