# Roomba+ 4.5.0b2

**The second beta of 4.5.0.** Everything in 4.5.0 is listed in
[4.5.0](v4.5.0.md); this page is what changed since
[4.5.0b1](v4.5.0b1.md).

Needs *Show beta versions* in HACS. Built on **roombapy-prime 0.8.0**,
which Home Assistant installs with it.

---

## Fixed

- **The care guide link opened Home Assistant's overview** instead of
  the guide, when clicked in Configure → Maintenance → Care guides, in
  the maintenance list or in a repair issue. Home Assistant's frontend
  takes over a link to its own address; the link now opens the guide in
  a new tab. Opening it with the browser's "open in new tab" worked
  before and still does.
- **iRobot's guide for your model** is now in the guide dialog too, not
  only on the separate page.
- **The maintenance overview** in Configure → Maintenance reads in your
  language -- "Replace the filter | OK | 45 hours | from the series
  profile" -- instead of `replace.filter`, `ok`, `hours`, `profile`, and
  has column headings.
- **Maintenance is the last entry** of the Configure menu.
- **The guide page says "When"** -- the interval, what is left and the
  last time -- as the dialog does.
- **Device triggers** *Cleaning started*, *Cleaning finished*, *Stuck*,
  *Docked* and *Error* fire again. They have not since 4.0.0: they
  compared the status sensors with display words the sensors no longer
  report. If you built automations on them and gave up, try again.
- **Clean in sequence** ends when either robot's entry unloads, instead
  of starting the second robot later anyway.
- **Diagnostics** redact cloud-login keys in every spelling
  (`AccessKeyId`, Cognito identity, IoT endpoint).
- **Demand cleaning on Prime robots** works: the option is offered,
  the dirtiest room the robot reports is cleaned after a mission (on the
  floor it is on, with the robot docked, never for missions from before
  a restart), and `auto_clean_dirty_rooms` chooses rooms on Prime. See
  [4.5.0](v4.5.0.md#demand-cleaning-on-prime-robots).
- **Presence scheduling** can be switched on for Prime robots.
- **An active blocking sensor** now stops demand cleaning; only a queued
  start did.
- **Switching demand cleaning or presence scheduling** takes effect at
  once, without a restart.
- **900-series room detection** runs in the background instead of
  holding up Home Assistant for up to a second and a half.
- **Less in the recorder:** room outlines and per-room lists are no
  longer written with every update.
- **Charging and battery error texts** follow iRobot's help article for
  each code; 53, 122 and 123, in no iRobot source, are removed.
- **Background work** no longer runs on after an unload or reload.

## Error texts from the robot's own app

**Breaking for automations that compare the error text.** A Classic
robot now reads the Classic app's texts, a Prime robot the Prime app's;
until now both read one table, mostly our own wording. On a Classic
robot the error sensor's state changes for 44 codes, for example:

| Code | Until b1 | Now |
|---|---|---|
| 2 | Debris extractors stuck | Brushes need cleaning |
| 36 | Bin full | Bin and sensors need cleaning |
| 89 | Mission runtime too long | Timed out |
| 102 | Charging error | Battery not charging |
| 451 | Tank low | Clean Base: tank low |

Compare the code (`error_code` on the vacuum, or the *Error – Last
code* sensor) rather than the text. Details in
[4.5.0](v4.5.0.md#error-texts-from-the-robots-own-app).

- **The model counts:** a Roomba 69x, an Essential and a robot on a
  Clean Base read the app's own wording for them; the robot's name
  stands where iRobot's text names it.
- **Our own texts remain only for the battery and charging errors**
  (101-121), where the app shows one line for all; checked against
  iRobot's article for each and corrected (107 "Battery too cold", 108
  "Battery not charging", 109 "Permanent battery fault").
- **iRobot's article for the error** as `help_url` on *Error – Last
  code*, the vacuum and the Prime error sensor, in the error-recurrence
  event, and as *Learn more* on the repair issue an error brings for a
  care task.
- **Care tasks an error points to** follow iRobot's help pages: on Prime
  also the wheels, bin, filter, charging contacts and wash dock; on
  Classic a few codes moved or went. 6 and 25 ("stuck near a cliff")
  show the cliff-sensor guide without making the cleaning due.
- **Clean Base status:** stopping, motor problem, bag almost full and
  hardware issue are new states.
- **Readiness** names nine more values a Classic robot sends, and 37
  and 38 read as the app reads them (battery failed, charge timeout)
  instead of both as a battery authentication error.
- `classic_label_unconfirmed` on the Prime error sensor is gone; its
  `error_text_source` says whose text it is.

## The care guides on GitHub

Every care guide, in all eight languages, is now also a page under
[docs/care](../docs/care/README.md): readable without Home Assistant,
with a section per group of robots where the guide differs. An expired
guide link points there. The pages are made from the integration's own
texts and drawings, so they say the same.

## Rooms on a 900-series

If your rooms looked wrong before 4.5.0 (a smeared map, doors in walls),
the new room detection does not clean up what was learned before.
[UPGRADING](../docs/UPGRADING.md#v450--from-v44x) says which two files to
delete to start the rooms afresh, and when it is worth it.

## What to test

1. **A care guide link** from Configure → Maintenance → Care guides and
   from the maintenance list, clicked directly, in the browser and in
   the companion app: does the guide open?
2. **Prime with demand cleaning on:** after a mission, does the robot
   go back for a room it rates dirty? And does `auto_clean_dirty_rooms`
   pick rooms rather than the whole house?
3. **An error on a Classic robot:** does the error sensor read what the
   iRobot app shows, and does `help_url` open iRobot's article for it?
   A robot on a Clean Base or a Combo dock: what does the error say when
   the dock has a fault?
4. Everything on the [4.5.0b1 list](v4.5.0b1.md#what-to-test) still
   applies.
